## 1. 核心决策与定位

首页不再是一个介绍页，而是**一块可以旋转、可以点的 3D 解剖人体**。整站的运动内容从这块人体往外展开：点身体上的发光热点 → 看到这个部位为什么痛 → 看到对它有帮助的运动 → 点进去看这项运动怎么练。

一句话记忆点：别人告诉你练什么，exsport 告诉你「哪里痛，该练什么」。

名称含义 expert + sport，与这个定位完全吻合。

## 2. 信息架构与页面清单

| 页面 | 路由 | 角色 |
|---|---|---|
| 首页（3D 人体主屏） | / | 全站唯一入口，3D 解剖人体 + 痛点热点 + 相关运动展开 |
| 分类页 | /sports | 10 项运动的总览与筛选（首页向下滚动可达，导航可直达） |
| 详情页 | /sports/:slug | 统一模板复用 10 次 |
| 关于页 | /about | 名字含义、内容来源与审校、免责声明 |

导航只放三项：人体（首页）、全部运动、关于。保持 3D 主体不被稀释。

原来单独的 /body 页面取消，伤痛地图与首页合并。若以后要做沉浸全屏模式，再加 /body 作为可选入口。

主流程：

```text
首页 3D 人体
  → 悬停热点：显示部位名 + 一句原因
  → 点击热点：该部位伤痛详情 + 有帮助的运动 2-3 项
  → 点击运动卡：进入运动详情页
  → 详情页：收藏 / 视频位 / 相关运动
首页向下滚动
  → 10 项运动网格 → 分类页 → 详情页
```

## 5. 逐区块规格（重点区块）

### 区块：首页 3D 人体主屏
- 区块目标：三秒内让人想拖动它，并让「哪里痛」变成浏览入口。
- 背景与素材：极浅蓝白渐变 + 低透明度几何图形（圆、圆角矩形、六边形网格）。
- 内容清单：3D 解剖人体、10 个痛点热点、定位语「expert + sport，哪里痛就练什么」、操作提示「拖动旋转 · 点击身体上的发光点」。
- 结构布局：人体居中占约 70% 高度，定位语在左上，操作提示在底部居中。
- 视觉重点：热点用青绿 #0FA9A0 脉冲光点，选中的部位高亮，其余轻微降透明度。
- 交互与动效：拖拽旋转、滚轮与双指缩放、悬停热点脉冲并浮出部位名与一句原因、点击热点高亮并联动第二屏、双击空白复位视角。
- 响应式规则：宽度小于 768px 时改用 2D 人体剪影 + 热点，保持同样的点击逻辑。
- 待确认项：解剖模型来源。

### 区块：痛点详情区
- 区块目标：把「痛」转成可执行的下一步。
- 背景与素材：浅色底，内容承载在玻璃卡片里。
- 内容清单：部位名称、常见原因 3-5 条、有帮助的运动 2-3 项（带卡片可跳转）、预防建议 3 条、免责声明一句。
- 结构布局：桌面左文右图（右图为该部位示意占位），移动端单列。
- 交互与动效：切换到新部位时 300ms 淡入上移；运动卡悬停浮起。
- 响应式规则：移动端改为底部弹层，可上滑查看全部内容。
- 待确认项：无。

### 区块：详情页模板
- 保持 v0.1 方案不变：顶部封面 + 基础信息四宫格 + 规则 + 入门五步 + 装备 + 训练要点 + 视频占位 + 演示评论 + 相关运动。
- 与首页的衔接：详情页底部增加「回到人体找痛点」的入口，形成闭环。

### 批量约定
分类页、关于页、首页其余区块统一规则：玻璃卡片、大留白、滚动淡入、悬停浮起、移动端单列。

## 6. 3D 解剖人体实现规格

模型来源三条路线（待你选一条）：

| 路线 | 视觉 | 体积 | 授权与成本 | 工期 |
|---|---|---|---|---|
| A 开源授权解剖模型（推荐） | 真实解剖 | 需压缩到 3-8MB | 多为 CC-BY-SA，需在页面署名 | 中 |
| B 你提供模型文件 | 取决于文件 | 取决于文件 | 由你确认授权 | 短 |
| C 程序化半写实人体 | 偏风格化 | 小于 1MB | 无版权问题 | 短 |

技术实现要点：

- 格式：glTF / GLB，three.js + @react-three/fiber + @react-three/drei 渲染。
- 压缩：用 Draco 或 Meshopt 压缩，纹理转 WebP，目标总体积不超过 8MB。
- 热点锚定：优先使用模型中已命名的解剖网格（取包围盒中心）；没有命名网格时，按人体骨骼锚点手工标定 10 个部位坐标。
- 交互：OrbitControls 限制旋转范围与缩放区间，避免转到看不清的角度；热点在模型外层用一个不可见点击球，避免被模型遮挡。
- 性能：首屏先渲染一张静态人体占位图（1MB 内）保证首屏快速可见，3D 资源用懒加载，加载完成后淡入替换；模型加载时显示进度提示。
- 降级：移动端与低性能设备切 2D 人体剪影 + 热点；3D 加载失败时自动落到部位速查按钮。
- 无障碍：10 个部位胶囊按钮可键盘操作，3D 画布不作为唯一交互方式；尊重系统「减少动态效果」设置。

## 7. 视觉风格规范

方向：科技玻璃，整体明亮，不用深色底。

| 用途 | 色值 | 说明 |
|---|---|---|
| 页面底色 | #F7FAFF → #E8F1FF | 极浅蓝白渐变 |
| 玻璃卡片 | rgba(255,255,255,0.65) + 模糊 16px | 1px 白描边 + 柔和阴影 |
| 主强调 | #0FA9A0 青绿 | 主按钮、热点、选中态 |
| 次强调 | #4A7CFF 蓝 | 链接与次按钮 |
| 点缀 | #6C5CE7 紫 | 光斑与几何图形，低透明度 |
| 主文字 | #0F172A | 对比度达标 |
| 次文字 | #5B6B84 | 说明文字 |

规范：圆角 16-24px，阴影低扩散，正文对比度不低于 4.5:1。模型用冷白到青绿的渐层材质，肌肉群可用同色系深浅区分，整体与页面底色协调。

字体：思源黑体 / 系统无衬线，标题 600，正文 400，中文正文 16px、行高 1.75。

## 8. 交互与动效清单

1. 3D 人体：旋转、缩放、悬停脉冲、点击高亮、双击复位。
2. 痛点切换：详情区 300ms 淡入上移。
3. 滚动淡入：区块进入视口上移 24px 淡入，400ms。
4. 悬停微交互：卡片浮起 4px。
5. 几何图形浮动：8-12 秒循环。
6. 收藏：缩放 + 填充色变化 + 轻提示，状态存浏览器本地。
7. 移动端：详情用底部弹层，上滑查看。
8. 无障碍：支持系统减少动态效果设置，3D 加载过程显示进度。

## 9. 响应式规则

断点：小于 768px 移动端，768-1199px 平板，1200px 以上桌面。

移动端：网格单列、导航折叠、3D 降级 2D 剪影、痛点详情改底部弹层、动效强度减半。

无障碍：图片替代文本、键盘可操作、热点带文字标签、不以颜色作为唯一信息。

## 14. 风险与假设

风险（按严重度排序）：

1. 真实解剖模型的授权与体积：开源模型需署名，未优化前可能几十 MB，直接影响首屏（高）。
2. 健康内容合规：伤痛内容必须写明「科普参考，不构成医疗建议」，并由你审校后才能定稿（高）。
3. 首页首屏性能：3D 抢首屏会让加载变慢，已用「静态占位图先上、3D 懒加载」规避（中）。
4. 十个部位的热点坐标需要手工校准，模型换一次就要重标（中）。
5. 移动端 3D 性能不稳，已定 2D 降级方案（中）。

假设：

- 采用开源授权或你提供的解剖模型，画面可旋转缩放。
- 伤痛部位先做 10 个，每个部位 3-5 条原因、2-3 项运动、3 条预防。
- 视频第一版只做占位框。
- 所有图片为占位素材。
